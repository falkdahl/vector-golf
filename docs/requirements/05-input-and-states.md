# 05 — Input, Game States & Attempts

## 1. Input Module `src/input.js`

- Exports `initInput()`, `getAimAngle()`, `setAimAngle(v)`, `getCharge()`, `isCharging()`.
- Tracks `keys` via `window keydown/keyup`; `e.preventDefault()` for `ArrowLeft/Right`, `Space`, `KeyR`, `KeyH`, `Escape`/`KeyP` (see `10-persistence-and-menus.md` priority).
- `getCanvasMousePos(e, canvas)` uses `game.getBoundingClientRect()` scaled to `LOGICAL_W/H` (see `02-canvas-system.md`).

## 2. Aiming — Orbit Around Ball

- Active only when `gameState ∈ {'AIMING','CHARGING'}`; ignored when `FLYING`/`WIN`/`rewardMenuVisible`/`mainMenuVisible`.
- `ArrowLeft`/`ArrowRight` (or `A`/`D` optional) rotate `aimAngle` time-based: `angle += dir * 1.6 rad/s * dt` (equivalently `ROTATION_SPEED≈2.5°/frame ≈90-150°/s` at 60fps), wrapping `[0,2π)`, smooth on hold (`e.repeat` handled via key state).
- Visuals `src/render.js:drawAim`: dashed orbit `r≈28-32` `rgba(0,0,0,0.2)`, aim line `30px` (`30+charge*50` when charging), indicator dot at `pos + (cos angle, sin angle)*orbitRadius`.
- **Persistence (REQ-019)**: `aimAngle` is preserved across death resets. Only `loadLevel(index)` (new hole) initializes `aimAngle = atan2(hole.y-tee.y, hole.x-tee.x)`. `resetBall()` shall NOT call `setAimAngle`.

## 3. Power Charging & Force Bar

- While `state==='AIMING'` and first `Space keydown` (`!e.repeat`), set `charging=true, charge=0, holdTime=0` and enter `CHARGING`.
- Each `update(dt)` while `charging`: `holdTime+=dt; charge=min(holdTime/MAX_CHARGE_TIME,1)` where `MAX_CHARGE_TIME=1.5`, linear (or `1-pow(1-t,1.5)` ease-out — document).
- On `Space keyup` while `charging`: `power = MIN_POWER + charge*(MAX_POWER-MIN_POWER)` (`MIN_POWER=50, MAX_POWER=600`), `launchBall(angle,power)`, `charging=false`. Tap `<0.1s` yields 5-10% power; hold ≥1.5s clamps at 100% (optional pulsate).
- Force bar `drawForceBar` under ball (see `03-rendering.md`) only while `CHARGING`; hidden otherwise. Aim line length scales `30+charge*50`.
- Launch is ignored if ball moving.

## 4. Attempts Counters — Max Attempts + Attempts Left + Free Shot + Treasure Rewards

- State in `src/main.js`: `currentHoleIndex` (0-based, displayed 1-based), `holeAttempts` (attempts used this hole, `0..maxAttempts`), `totalAttempts` (=`attempts` alias, total across run), `maxAttempts` (hidden per-run max, starts `10`, **static — no `Max Attempts +5` reward; see `09`**; legacy `Max Attempts +5` is removed and superseded by `Free Shot`), `totalHoles = LEVELS.length` (see `08-level-generation.md`). Derived `attemptsLeft = max(0, maxAttempts - holeAttempts)` — **hidden max, shown left**. Free Shot state `supply.freeShot` + `isFreeShotActive` (see `07-modifiers.md` §5.2) lives alongside counters. Treasure/reward state `rewardPending`/`rewardMenuVisible`/`treasure` (see `09` §3, `08` §4) lives alongside.
 - **Increment branching on Free Shot** (`handleLaunch`, see `07` §5.2 & `09` §3): `R` without launch does not increment. On each `launchBall`:
  - **Auto-arm on last attempt (no manual hotkey)**: before branching, if `!isFreeShotActive && supply.freeShot >0 && getAttemptsLeft() <=1` (i.e. this launch would be the last counted attempt, `holeAttempts == maxAttempts-1`), automatically set `isFreeShotActive=true` and `syncFreeShotGlow()` so the last attempt becomes free **without manual `4` (4 is now `rotate`)**. This check runs at launch initialization; Free Shot **has no hotkey** (4 is `rotate`).
  - If `isFreeShotActive===true && supply.freeShot >0` (Free Shot auto-armed): **free launch** — do **not** increment `holeAttempts`/`totalAttempts`; instead `supply.freeShot = max(0, supply.freeShot-1); if (supply.freeShot >0) keep `isFreeShotActive=true` (persist auto-armed) else `isFreeShotActive=false`; `updateHotbarUI(); saveProgress();` visually keep/clear golden glow per remaining supply (ball glow visible only while `isFreeShotActive`, see `07` §5.2) and HUD `(+Y)` updates; `attemptsLeft` unchanged, no Game Over check. Ball still launches normally. **Free Shot persists** while supply remains (consecutive auto free launches while `supply.freeShot>0` on last attempts).
  - Else (normal launch): do `holeAttempts++; totalAttempts++; attempts=totalAttempts; attemptsLeft = maxAttempts - holeAttempts;` then `updateAttemptsUI()` (which updates HUD `Attempts Left: X (+Y)`) and `saveProgress()`. **Do NOT check Game Over immediately** after this launch (see §5): the last shot is allowed to finish (`FLYING` continues, `checkWin`/treasure/OOB/bounce still run) and can still win. If it then **fails** (hits OB/water/edge out of bounds), `update()` shows **Game Over immediately** without resetting to tee (see §5). Free launches never trigger Game Over. **Reward menu is not triggered by shot count**; it is triggered by hole-start (any hole except first, see `09` §3) and by treasure hit (`08` §4, `04` §6, `09` §3) only — but never when out of attempts when the failure occurs (Game Over wins).
- **HUD** is canvas-drawn `drawHUD` (see `03-rendering.md`) with strip behind text, visible in `AIMING`/`CHARGING`/`FLYING`. Now shows **`Attempts Left: X (+Y)`** (where `X = max(0, maxAttempts - holeAttempts)` and `Y = supply.freeShot`, e.g. `Attempts Left: 5 (+5)` when `supply.freeShot=5`) **instead of `Attempts: X` or `Attempts Left: X` without `(+Y)`**, centered; left still `Hole: N/M`, right `Total: Y`. Win overlay (DOM, final hole only) shows `★★★` three stars + `Course Completed!` + `Total: Y` (still `totalAttempts` — free launches not counted, no hole/attempts-this-hole info). Game Over overlay shows `Game Over` big text over green `Continue` button with `Press R to continue` (see §5).
- **Lifecycle**: death (`resetBall`, tree bounce) does not reset counters and does **not** clear `isFreeShotActive` (armed free shot survives death until used) nor `treasure` (treasure stays until collected, even through death); `R` during play does not reset; hole advance (`handleNextHole`, see `09-rewards-and-progression.md`) resets `holeAttempts=0` (so `attemptsLeft` resets to `maxAttempts`) but keeps `totalAttempts` and keeps `maxAttempts` (static `10`) and keeps remaining `supply` (spatial `amplify`/`nullify`/`flip`/`rotate` minus win consumption, `freeShot` minus launch consumption) but clears `isFreeShotActive=false` and regenerates `treasure` for next hole (`isCollected=false`); `WIN`/`GAME_COMPLETE` → `R`/`resetGameAfterWin`/`startNewGameFromMain`/`endRun` resets all to `0` with `maxAttempts=10` and `supply={1,1,1,1,0}` (`rotate:1`) + `isFreeShotActive=false` + new `treasure` (see `10-persistence-and-menus.md`) and also resets `areaUpgradeCount` etc. **Game Over** → `Return to Main Menu` does `clearProgress()` (see `10`) and returns to entry main menu. **Free Shot supply** starts `0` (passive, `+0` in HUD) on new game (see `07` §6); **Rotate supply** starts `1`.
- **No Max Attempts reward**: `Max Attempts +5` has been removed; `maxAttempts` stays `10` (legacy `maxAttempts>10` from old saves is clamped on load but never increased in-game). Free Shot is the consumable that makes an attempt not decrease `Attempts Left`.

## 5. Game States & Transitions — including GAME_OVER

States (string enum in `src/main.js`): `AIMING`, `CHARGING`, `FLYING` (covers drifting), `WIN`, `GAME_OVER` (no `REST_CHECK`). Transient banner states `holeBannerVisible`/`attemptsBannerVisible` (see `11-banners.md`) block `AIMING`/`CHARGING` input while visible (same blocking as `rewardMenuVisible`).

**GAME_OVER** (immediate on last-attempt failure): when the **last counted attempt fails** ( `holeAttempts >= maxAttempts` i.e. `attemptsLeft <=0` ) without having won the hole, **after allowing the last flight to finish**, trigger `gameState='GAME_OVER'` **as soon as the failure is detected** (`terrainHit`/`waterHit`/`edgeOut` in `update()` while `FLYING`), **without resetting to tee** (`resetBall()` is NOT called). Hide/clear `rewardMenuVisible`/`rewardPending`/`rewardOffered` (Game Over **takes precedence** over any pending or visible reward), and show **Game Over** screen as `Game Over` big text over green `Continue` button with `Press R to continue`. The last shot where `attemptsLeft` becomes `0` is **allowed to finish**: `FLYING` continues until win ( `checkWin` can still win on the last flight) or until OB/water/edge failure — which then shows Game Over immediately instead of `resetBall()`. If `supply.freeShot>0`, the **last attempt is auto-armed** to be free (see §4) so `attemptsLeft` never becomes `0` from that launch and failure does not trigger Game Over. Fallback: if Game Over was not triggered via failure (e.g., ball stuck), starting a new attempt via `handleLaunch` while `attemptsLeft<=0` also shows Game Over. While `GAME_OVER`, `updateBall`/`handleLaunch`/modifier placement/toggle (`1/2/3/4`)/`maybeShowRewardMenu`/`pause` are blocked; only green `Continue` (click or `R`) is accepted (also `Escape`/`Enter` for compat). That action does `clearProgress()` (remove `STORAGE_KEY`, reset `currentHoleIndex=0, holeAttempts=0, totalAttempts=0, maxAttempts=10, supply={1,1,1,1,0}` with `rotate:1`, `isFreeShotActive=false` passive, `areaUpgradeCount=0, modifiers=[]` including `rotate`, see `10`) and returns to entry main menu (`mainMenuVisible=true, isInLevelPause=false`) removing active game from main menu. No `Next`/`Continue` from Game Over other than this; the run is cleared from memory (reload shows entry with no `Continue`).

- `AIMING`: ball at tee `vel=0`, accept aim+Space→`CHARGING`, modifier placement allowed (see `07-modifiers.md`), hotbar visible (see `07-modifiers.md`).
- `CHARGING`: `Space` held, update force bar, angle may be locked (document), release → `launch()` → `FLYING`.
- `FLYING`: physics updates, wind always applied (even when slow), collision/edge/hole checked each tick; no aiming/charging/modifier input; persists while drifting (no auto-rest).
- `WIN`: ball entered **final** hole (see `04-physics-and-collision.md` and `09-rewards-and-progression.md` §1). `vel=0` frozen, Victory overlay shown **only after last hole** as `★★★` + `Course Completed!` + `Total: Y` over green `Continue` with `Press R to continue`, physics paused, input blocked except green `Continue`/`R` → main menu clearing `STORAGE_KEY` (per `09/10`). Non-final holes auto-advance immediately without entering `WIN` or showing Victory (see `09` §1-§2).

`resetBall()` (idempotent, synchronous, callable from collision/OOB/`R`):

- `ball.pos={...tee}; ball.vel={0,0}; ball.isMoving=false; charge=0; charging=false; state='AIMING';` clear win/Game Over overlay if not in those states; **do NOT touch** `aimAngle` (per §2), `holeAttempts`/`totalAttempts`/`maxAttempts`, `supply`/`isFreeShotActive`/`areaUpgradeCount`, `modifiers` (they persist through death — including armed `isFreeShotActive`), `treasure` (stays until collected, even through death). No `bouncy` (trees always bounce, see `04` §5).

`R` key:
- In `AIMING`/`FLYING` → `resetBall()` (keeps aim angle, no counter increment) **except on last attempt flight**: when `getAttemptsLeft() === 0` (last counted attempt has been launched, `holeAttempts === maxAttempts`, ball is `FLYING` on final attempt), `R` is **disabled** — `resetBall()` is not called, ball must play out (`FLYING` continues until win or OB/water/edge failure → Game Over). This prevents resetting during the final attempt's flight, but `R` remains enabled on second-to-last attempt (`attemptsLeft ===2` before launch / `1` during its flight). `R` before last attempt at tee (`AIMING` with `1` left) is still enabled (reset to tee is no-op).
- In `WIN` (`Course Completed!` final) → `R` (or green `Continue` click) → `returnToMainMenu()` → `clearProgress()` removing active game from main menu (see `09/10`); same for `GAME_OVER` (`Game Over` big text + green `Continue`) → `R` or green `Continue` → `handleGameOverReturn()` → `clearProgress()` removing active game.
- When `rewardMenuVisible` → `R` means **re-roll** (see `09-rewards-and-progression.md` §6, hotkey `R` not `0`), not reset.
- When `mainMenuVisible` (pause/entry) → `R` is blocked (pause uses `Continue`/`Escape`/`P`).

Attempts/hole progression (see `09-rewards-and-progression.md` for full trigger including supply consumption): non-final win → **auto-advance** (no Victory/Next) → consume modifiers from supply (see `07-modifiers.md`), clear modifiers, `currentHoleIndex++`, `holeAttempts=0`, `loadLevel(currentHoleIndex)`, `state='AIMING'`; final win → `★★★ Course Completed!` + `Total: Y` + green `Continue` (`Press R to continue`) → `R`/`Continue` → `clearProgress()` removing active game → main menu (see `10-persistence-and-menus.md`).

## Acceptance Criteria

- [ ] Orbit and aim line update at 60fps, `ArrowRight` 1s ≈90-150°; `aimAngle` persists after death but re-initializes on new hole.
- [ ] Space tap/hold 0s/0.75s/1.5s shows 0%/50%/100% bar; bar only under ball while `CHARGING`; color green→red.
- [ ] Normal `holeAttempts`/`totalAttempts` increment exactly once per counted launch; `maxAttempts` starts `10` static (no `Max Attempts +5`), `attemptsLeft = maxAttempts - holeAttempts` shown as `Attempts Left: X (+Y)` where `Y=supply.freeShot` (e.g. `Attempts Left: 5 (+5)`); **free launch** (`isFreeShotActive && supply.freeShot>0` via **auto-arm only, no manual `4`**) does **not** increment `holeAttempts`/`totalAttempts` and consumes `supply.freeShot--` exactly once but **persists** `isFreeShotActive=true` while `supply.freeShot>0` after decrement (only clears when supply reaches `0`). No legacy `freeShots` gating. When `getAttemptsLeft()<=1` at launch init and `supply.freeShot>0`, free shot **auto-arms** making that launch free (4 is now `rotate`).
- [ ] `resetBall` reappears at tee within 1 frame on hit/edge/`R` (except during last attempt flight where `getAttemptsLeft()===0` and `R` is disabled and ball must play out) and does not interrupt HUD counts nor clear `isFreeShotActive` nor `treasure`; `maxAttempts` persists static, `holeAttempts` only reset on hole win/Game Over, `supply.freeShot` persists until consumed, treasure persists until collected or hole advance. On second-to-last attempt (`Attempts Left: 2`/`1` during its flight) `R` still works; only on last attempt flight (`0`) `R` does nothing.
- [ ] No launch when `FLYING`; no aiming while `WIN`/`GAME_OVER`/`rewardMenuVisible`/`mainMenuVisible`.
- [ ] After `holeAttempts == maxAttempts` counted launch, `gameState` remains `FLYING` and `Game Over` is **not** shown immediately at launch; ball is allowed to finish last flight and can still win; HUD shows `Attempts Left: 0 (+Y)` during that flight (`Y=supply.freeShot` still shown). If that flight then **fails** ( `terrainHit`/`waterHit`/`edgeOut` while `attemptsLeft<=0` ), `Game Over` is shown **immediately on failure** without `resetBall()` to tee: `gameState='GAME_OVER'` with big `Game Over` over green `Continue` with `Press R to continue` (hides any `rewardMenuVisible`/`rewardPending` instantly), `R` or green `Continue` does `clearProgress()` (resets `supply` to `{1,1,1,1,0}` with `rotate:1` + clears `isFreeShotActive` passive and regenerates `treasure`) and returns to entry removing active game (reload shows no `Continue`). If last flight wins, no Game Over. Reroll that makes `attemptsLeft 0` still shows Game Over immediately (reroll is not a launch; cost is counted attempt). Free-shot auto-arm at `<=1` (no manual `4`) prevents exhausting attempts when supply exists.
- [ ] HUD shows `Attempts Left: X (+Y)` (not `Attempts: X` and not `Attempts Left: X` without `(+Y)`), `X = maxAttempts - holeAttempts` and `Y = supply.freeShot`, e.g. `Attempts Left: 5 (+5)` when `supply.freeShot=5`, updates after each **counted** launch; free launch leaves `X` unchanged, decrements `Y`, and keeps `isFreeShotActive` true while `supply.freeShot>0` after decrement (persists), only clears when supply reaches `0`; if `supply.freeShot>0` when `getAttemptsLeft()<=1` at launch init, free shot auto-arms (`isFreeShotActive` becomes true) making the last attempt free (no manual `4`, 4 is `rotate`); `maxAttempts` never increases; reward menu not triggered by shot count.
