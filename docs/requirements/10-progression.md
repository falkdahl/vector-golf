  - `Escape` / backdrop click before any pick cancels back to main menu without starting run (like old loadout cancel, not required but allowed). Empty spatial slot is gray `rgba(128,128,128,0.28)` `border #7a7a7a` with no icon/hotkey.

### 2.2 Passive Bag Slots — Stackable, No Hotkey, Not Placeable
- **Types:** `fieldExtender` (display `Field Extender` `+20% area`), `rangeModifier` (alias `powerCell`, display `Range Modifier` `+20% strength`), `freeShot` (display `Free Shots` `+1 attempt`). ## 3. Points System (replaces Coins)

### 3.1 Constants
- `POINTS_PER_ATTEMPT = -1` (each counted attempt costs 1 point, never free beyond `freeShot` stock).
- `POINTS_PER_HOLE = 10` per hole cleared (`10p - cleared hole` row).
- `POINTS_PER_MODIFIER = 10` per unique modifier the ball travelled through during the hole (distinct modifier ids entered, all spatial `magnifier/liquifier/deflector/rotator` count if ball was inside `dist < radius` at any tick during that hole's flight).
- `POINTS_FIRST_ATTEMPT_BONUS = 50` if `holeAttempts===0` at win (first attempt, no prior failure; `holeAttempts` increments on each failure reset; clearing with `holeAttempts===0` means first attempt — award 50).
- No `COURSE_COMPLETE_BONUS` (`100` removed). Points are sum of above per hole, aggregated across run.

### 3.2 Run Points Calculation — Clearing Shot Only
- Per hole cleared: `holePoints = 10 (cleared hole) + traversedOnClearingShot*10 + (firstAttempt ? 50 : 0) - holeAttemptsCount` where `traversedOnClearingShot` is number of distinct field modifiers the ball was inside **on the shot that cleared the hole** (tracked per-shot `modifiersTraversedThisShot`, not the whole hole), and `holeAttemptsCount` is failures before win. Example: `10p - cleared hole` + `20p - Modifier Bonus (x2 on clearing shot)` + `50p - First Try Bonus` - `3p - three attempts` = `77p` net for that hole. Only the clearing shot's modifiers count.
- `totalPoints` is incremented incrementally `-1` per failed attempt (visible in HUD immediately) and `+10 + traversedOnClearingShot*10 + firstBonus` at each hole win (so net per hole is as above).
- Run totals: `runPoints = sum(holePoints across cleared holes)` (already reflected in `totalPoints` via incremental).
- `totalPoints` may be negative, HUD shows negative. No clamp. `STORAGE_KEY` persists `totalPoints` for resume.

### 3.3 HUD — Point Tracker
- HUD `#hud-total` text changes from `Total: Y` to **`Points: N`** (label `Points:` not `Total:`). Updates after each attempt result and after each hole win. `updateAttemptsUI()` sets `hudTotal.textContent = 'Points: ' + getTotalPoints()`.
- `#hud-attempts` still `Attempts Left: X (+Y)` for freeShot.
- `#progression-coins-display` removed/hidden.

## 4. End-of-Hole Summary (replaces Coin Summary on Run End) — Detailed Breakdown, No Unlock Texts

- **Trigger:** show the summary **on the end of each hole** (non-final win `advanceHole` and final win `returnToMainMenu` both), not only at run end. After `checkWin` succeeds and before `loadLevel(next)` for non-final, call `showHoleSummary(holeIndex, pointsBreakdown)` which sets `holeSummaryVisible=true` and pauses game (like `coinSummaryVisible` but per-hole). For final hole win, same summary before `WIN` victory screen or after. If hole was failed via `End Run`/`Game Over`, summary also shown with current run points.
- **Overlay:** `#coin-summary-overlay` is repurposed as **Points Summary** (keep id for compat, or alias `#points-summary-overlay`). `position:absolute; inset:0; display:flex; align-items:center; justify-content:center; background:rgba(0,0,0,0.55); z-index:14` over the loaded level (`mainMenuVisible=false`, terrain dimmed, not over splash). Card `.coin-summary-card` is transparent `background:transparent` (no black), title `h3` text `Hole Complete` (or `Run Complete` for final) per spec, big amount `#coin-summary-amount` shows **`+X points`** (text contains `+` and number and word `points` case-insensitive, e.g. `+70 points`, not `💰`), icon `💰` not shown in big row (or hidden), moneybag replaced by word `points`. The required phrasing for the big row is `+<totalPoints> points` (amount `+` number before `points`).
- **Breakdown rows chars:** `#coin-summary-details` rows each contain amount + ` - ` + label + `(xN)` but with **`p` suffix** on amounts, not `💰`. E.g. `10p - cleared hole` (base 10 for each hole cleared), `20p - Modifier Bonus (x2)` for 2 modifiers `*10`, `50p - First Try Bonus` for first-attempt, `-3p - three attempts` / `-3p - Attempts (x3)` for 3 attempts. Normative: rows shall contain `p` (lowercase `p` immediately after number, e.g. `10p`, `50p`, `-1p`) and `-` and label containing `cleared hole` for base row and `attempt` for attempts row, and `(x` for modifier/attempt rows where applicable. Moneybag `💰` shall not appear in visible breakdown (`querySelector('#coin-summary-details').textContent.includes('💰')===false`). **No unlock texts:** `Loadout slot unlocked` / `New items in the shop` / `New Course Unlocked` shall not be visible on `Hole Complete` (`#coin-summary-unlock`/`#coin-summary-shop`/`#coin-summary-course` are `hidden`/`display:none` when hole summary visible).
- **Gap & style:** same as before `gap 16-20px` between big row and breakdown, center aligned `align-items:center`, `text-align:center`, gold attention not required but allowed. `Continue` button `#coin-summary-ok` text `Continue` closes summary and either advances to next hole (non-final) or returns to main menu (final/End Run). Two-phase dismissal: first input fast-forwards animation, second closes, same as before but now per-hole.
- **Source of points for summary:** `holeModifiersTraversed` (unique count for that hole), `holeAttemptsBeforeWin`, `firstAttemptBonus` boolean. Summary total `holePoints = 10 (cleared hole) + traversed*10 + (first?50:0) - attempts`. Run total may be shown as big amount or hole amount; spec says big summary says `points` on big summary and just `p` on breakdown rows — implement hole-specific big amount as `+holePoints points` (`+7 points` for 10-3 example) and breakdown as above, or run total as `+runPoints points` with per-hole breakdown aggregated. Either acceptable if `p` and `points` present and math matches `10 + traversed*10 + firstBonus - attempts`.
