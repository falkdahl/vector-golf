# 12 — Mobile Support (Phone Landscape, Touch Controls)

- **ID:** 12-mobile
- **Type:** Functional + UI
- **References:** `01-foundation.md` (logical space, DOM, resize); `02-rendering.md` (HUD/overlays); `05-modifiers-and-bag.md` (placement/drag/stacking); `06-run-rules.md` (input/Escape/aim/charge); `13-pwa.md` (installed fullscreen landscape, iOS install hint)

> Mobile phone adaptations. Desktop mouse/keyboard behavior unchanged. All touch equivalents must produce identical game-state effects as their keyboard/mouse counterparts.

## 1. Detection & fullscreen

- `isMobilePhone()`: true on phone clients — phone UA (`Android.*Mobile|iPhone|iPod|Windows Phone|IEMobile|Opera Mini|Mobile`) OR (`navigator.maxTouchPoints>0` + `matchMedia('(pointer:coarse)')`) + `?mobile=1` force flag for testing (also `window.__isMobilePhone`, `window.__isMobileMode` hooks).
- On mobile the game is landscape-only. `requestMobileFullscreen()` requests fullscreen on `#game-container` (fallback `document.documentElement`, `webkitRequestFullscreen` on iOS) and then locks to landscape via `lockLandscapeOrientation()`. The lock MUST be chained after the fullscreen promise resolves — `screen.orientation.lock()` issued synchronously next to `requestFullscreen()` rejects (no fullscreen element yet), silently leaving the game unlocked and letting phones fall back to portrait (observed after skipping the first cutscene). Mobile-guarded (never attempted on desktop). Best-effort: no-op where the API is missing (iOS Safari); the rotate guard below is the hard guarantee.
- Lock re-assertion points: boot-gate continue, every Play tap (`handleCoursePlay`), cutscene Skip, banter Skip, `fullscreenchange`/`webkitfullscreenchange` (re-lock when entering fullscreen), `screen.orientation` `change` / `orientationchange` (re-lock + re-sync guard), automatic transitions (`playCutsceneWrapped` entry/exit, `loadLevel`), and a frame-loop watchdog that re-asserts the lock whenever the viewport is portrait while fullscreen (throttled). Skipping a cutscene therefore re-locks landscape instead of dropping to portrait. `requestMobileFullscreen()` is idempotent: when already fullscreen it only re-asserts the lock and never re-requests fullscreen — re-requesting the live fullscreen element silently released `screen.orientation.lock()` on some Android builds (no `fullscreenchange`), letting the phone rotate back to portrait across transitions (main menu → cutscene → level). `ensureMobileLandscape()` is the shared idempotent helper (no-op on iOS and standalone PWA where the rotate guard / manifest covers orientation).
- Portrait rotate guard (`#mobile-rotate-overlay`, container-bound `absolute inset:0`, `z-index:50` — above game overlays/skip buttons, below boot gate/loading screen; `hidden` under the boot gate like other chrome): visible in mobile mode iff the viewport is portrait (`innerHeight > innerWidth`), synced from `syncMobileUI()` + `resize`/`orientationchange`/`fullscreenchange` via `syncRotateOverlay()` (`window.__syncRotateOverlay`, `window.__isRotateGuardVisible` hooks). While up it covers the container so all touch input is blocked, and gameplay key paths are gated too: the input state getter reports `ROTATE` (charge can never start; releasing then cancels instead of launching), `R`/reset returns early, canvas `mousedown` placement no-ops. Dismisses automatically on returning to landscape. This is what enforces landscape-only on iOS (no Orientation Lock API) and whenever the lock call fails.
- Exiting fullscreen must be recoverable: `#mobile-fullscreen-button` (`⛶`, top-right below HUD) visible on mobile whenever `document.fullscreenElement==null` (and not already an installed standalone PWA, see `13-pwa.md`) and the boot gate is dismissed, including on the main menu (so fullscreen can be entered before starting) but hidden on other blocking chrome (pause/cutscene/banter/summaries/`WIN`/`GAME_OVER`); click re-requests landscape fullscreen. On iOS browsers, which have no element Fullscreen API, the tap instead shows `#toast` with `Fullscreen isn't supported in iOS browsers. Tap Share → Add to Home Screen to play fullscreen.` (never attempts fullscreen). `fullscreenchange` re-syncs UI. Never auto-forces fullscreen on desktop.
- Fullscreen CSS: the container fills the viewport in EVERY mode — windowed, F11/OS fullscreen, the mobile `⛶` button, and installed PWA (`#game-container { width:100dvw; height:100dvh; background:#2E2E2E }`, `100vw`/`100vh` fallback first, no `aspect-ratio`). Each canvas is a centered 16:9 "contain" box (`width:min(100dvw,100dvh*16/9)`, `height:min(100dvh,100dvw*9/16)`, `transform:translate(-50%,-50%)`) so the whole 1280×720 level is always visible and undistorted (circles stay circles), and the leftover area is painted the OB colour `#2E2E2E` instead of black bars. There is intentionally NO `:fullscreen`-specific sizing (the base layout already fills the viewport, so F11/PWA which do not set `fullscreenElement` behave identically) and no per-canvas letterbox variant (one misrendered on phones: clipped/huge terrain, wrong cutscenes). The 3px border / 8px radius / box-shadow was removed from the game canvases so the play area blends into the OB background. Mobile chrome (hamburger, reset, `⛶`, aim/launch, journal) anchors to the true screen corners and the 28px `#hud` strip spans the full window width; overlays remain container-bound. Input mapping is unchanged (`getCanvasMousePos`/`getCanvasTouchPos` use the canvas `getBoundingClientRect()`, which is now the centered 16:9 box). The menu parallax splash is a centered box whose aspect ratio is clamped to 16:9–20:9 (`width:min(100dvw,100dvh*20/9)`, `height:min(100dvh,100dvw*9/16)`): it fills the window on wide phones (up to 20:9) but never grows taller than 16:9, and ultra-wide screens are capped at 20:9 with the OB grey already visible; the art is `object-fit:cover` so it never distorts. `fullscreenchange` re-runs `setupCanvas()` + `resizeWindOverlay()` + `syncMobileUI()`. `touch-action:none` on container + canvases to prevent scroll/pinch-zoom; viewport meta includes `maximum-scale=1.0, user-scalable=no, viewport-fit=cover`.

## 1b. Mobile performance budgets (phone only; desktop unchanged)

- Backing-store DPR capped via `effectiveDPR()` in `src/main.js`: `min(devicePixelRatio, 1.5)` on mobile (uncapped desktop). Sustained `<45fps` over 120 frames auto-degrades once to cap `1.0` + `setupCanvas()`/`resizeWindOverlay()` (cap published as `window.__mobileDPRCapValue` for cutscenes). Physics stays logical; only backing resolution changes.
- DPR consistency (correctness, not just perf): EVERY 2D transform must use the capped value — `setupCanvas`, `redrawBottom`, `render()`, and `renderCutscene` (`src/cutscene.js` local `effDPR()`). A raw-`devicePixelRatio` transform on a capped buffer draws scenery ~2× oversized and clipped (regression seen on DPR-3 phones: giant top-left terrain, wrong cutscenes).
- Single-canvas blit (all platforms; biggest win on phones): gameplay renders on `#game` only — terrain `drawImage` + bubbles + hole-overlay `drawImage` plus dynamic draws (two blits, still zero per-frame path ops for scenery). `#bg-canvas` is `display:none` during gameplay so the compositor skips a full-screen dead layer (two stacked 2D canvases forced a per-frame blend even though terrain never moves). Terrain buffer (`src/render.js` sliding window: `prepareCourseStaticWindow`/`ensureCourseStaticImage`/`evictCourseHolesExcept`/`getCourseStaticImage`/`drawCourseStaticImage`): at most 2 holes (current + next) at `staticCacheDpr()` (`1` on mobile ≈ 7MB worst case — display DPR on desktop ≈ 28MB at dpr 2); current hole renders synchronously on Play click / hole advance / DPR change with no state reset, next hole prebuilds in one background task during play, previous holes evicted on advance. Hole 0 of every staged course is additionally pre-warmed from the main menu (bounded first-hole cache, 4 mobile / 2 desktop, largest first) and adopted on start, so course buttons start instantly. Hole overlay (`renderHoleOverlay`/`drawHoleOverlay`, current hole only, +1 canvas): trees/bricks + hole blitted after bubbles so bubbles sit under trees. Treasure stays dynamic. Per-level `renderStaticScenery`/`drawStaticScenery` remains as deep fallback only. Fallback to direct draw if a blit is unavailable.
- Wind overlay on mobile: 24 streaks × 12 nodes (desktop 48×24), `antialias:false`, `depth:false, stencil:false`, `powerPreference:'low-power'`, pixel ratio capped 1.0 (all in `src/windThree.js`; quality chosen once at `initWindOverlay`).
- Wind visuals tick once per rAF (`tickWindVisual(frameDt)` in `loop()`); `update(dt)` fixed steps never tick wind or touch hotbar DOM (banner timers/physics unchanged). Blocked-state branches set `needHotbarSync`, flushed once per frame.
- Modifier wind arrows (`src/render.js`): per-modifier bounding-box precheck skips most of the 32×18 cell scan without `hypot`; canvas-shadow pass skipped on mobile (dark outline underneath keeps readability, shapes/colors identical).
- DOM churn guards: passive hotbar slots rebuild only on counts/toggle/armed signature change (`dataset.passSig`); HUD hole/attempts/points text assigned only when changed.
- Compositor: parallax splash is static on mobile (no per-frame `translate3d`, no touch-follow); `#golfbag-container`/`#journal-container` drop `backdrop-filter: blur` under `.mobile-mode` (flat `rgba(0,0,0,0.55)`).

## 2. Touch overlay controls (lower-right)

- `#mobile-controls` (`absolute; bottom:12px; right:12px; flex; gap:8px; z-index:7`): three `56×56` round buttons — `#mobile-aim-left` (`◀`), `#mobile-launch` (`●` + `LAUNCH` label), `#mobile-aim-right` (`▶`). `touch-action:none`, `user-select:none`, semi-transparent dark with white glyphs.
- Equivalence (identical state effects, same blocking as keyboard):
  - Hold left/right = `ArrowLeft`/`ArrowRight` held (`1.6 rad/s` rotate, wrap `[0,2π)`, blocked in `FLYING`/menus/banners — same as `06-run-rules.md` §2).
  - Press-and-hold launch = `Space` held (`charge=min(holdTime/1.5,1)`), release = `Space` keyup (`power=50+charge*550`, `launchBall`, counted/free-shot accounting per `06-run-rules.md` §3).
- Implemented via `src/input.js` touch API (`touchAimStart/End`, `touchChargeStart/End`) sharing the same `keys`/`charging`/`onLaunch` path as keyboard (not a parallel physics path). Hold buttons share ONE holder token fed by both Pointer Events (`pointerdown` + `setPointerCapture`, `pointerup`/`pointercancel`/`lostpointercapture` release) and Touch Events (`touchstart` press, `touchend`/`touchcancel` release): whichever fires first wins, duplicates are ignored, only the matching release clears (all idempotent). Pointer-only missed holds where `pointerdown` arrives late; separate emulated-mouse bindings were removed. `touchstart` `preventDefault` + `contextmenu` suppression + `-webkit-touch-callout:none` block double-fire/long-press menu. Visible only in mobile mode while gameplay chrome is visible (same visibility as `#bottom-bar`: `AIMING`/`CHARGING`/`FLYING` + reward open, hidden in pause/menus/banners/`WIN`/`GAME_OVER`/summaries/cutscene/banter/starting overlay).

## 3. Touch drag & drop + double-tap

- Canvas `touchstart/move/end` (`passive:false`) mirror mouse placement/drag:
  - `getCanvasTouchPos(touch)` maps via container rect to logical coords (same formula as `getCanvasMousePos`).
  - Armed + tap canvas = `placeModifier` (OOB-checked after snap, same as click).
  - Touch on placed bubble (nothing armed) + move = board drag (same `draggingIdx/draggingMates/dragOffset` stack snapshot, snap commits only on release, canvas→bag drop over spatial slot supported).
  - Bag tap = left-click: tapping an occupied spatial slot toggles arm/disarm via `selectBagSlot()` (identical to click/`1–3`); while armed, tapping anywhere on the field places there via `placeModifier()` (OOB-checked after snap). Taps never rely on click synthesis because `touchstart preventDefault()` suppresses the emulated mouse click.
  - Bag→level drag = hold-left-mouse drag: finger down on an occupied spatial slot + drag onto the field + lift places at the lift point via `placeModifier()` (same as mouse press-drag-release). Arming happens after `>6px` move (`BAG_DRAG_THRESHOLD_PX`); release ends on the grid's `touchend` (touch events retarget to the touchstart element, so the canvas handler never sees bag-originated releases): over a spatial slot moves/swaps, over the canvas places at the release point (same as mouse bag-drop), elsewhere deselects.
  - DOM churn guard: while a bag touch (`bagTouch`) is in progress the `#hotbar-grid` must NOT rebuild `innerHTML` (class-only selection updates; pending rebuild deferred to the next sync after `touchend`). Rebuilding mid-touch detaches the touchstart target so the retargeted `touchend` never arrives and the drag is lost. `touchcancel` on the grid clears `bagTouch` like the canvas handler.
- Double-tap on a placed modifier's area-of-effect = right-click: two taps within `300ms` and `24px` call the shared `handleRightClickAt(x,y)` path (stack splits if stacked, else pickup to empty slot or `Golfbag is already full` toast, armed deselects first — identical to `contextmenu` per `05-modifiers-and-bag.md` §6). Single-tap behavior unchanged (tap without drag on unarmed modifier = no-op; tap with armed = place). Emulated mouse events suppressed via `preventDefault`.

## 4. Hamburger menu (Escape equivalent)

- `#mobile-menu-button` (`☰`, `44×44`, `absolute; top:36px; left:12px` — just below the 28px `#hud`; `z-index:7`): visible on all platforms (desktop + mobile) while gameplay chrome is visible (same rule as `#bottom-bar`: `AIMING`/`CHARGING`/`FLYING` + reward open, hidden in pause/menus/banners/`WIN`/`GAME_OVER`/summaries/cutscene/banter/boot gate/starting overlay).
- Click/tap dispatches the identical Escape path as keyboard (`Escape` keydown handling in `src/main.js`: deselect → close help/confirm/reward-skip → open in-level pause / resume — per `06-run-rules.md` §4 and `08-campaign-and-menus.md` §6). No separate pause logic; synthetic `Escape` keydown event reused so behavior can never diverge.
- Touch firing: `touchend` (with `preventDefault` to suppress the emulated click, same pattern as bag taps) + `click` fallback for mouse, with a 600ms post-touch click suppress so one tap can never dispatch twice (pause opening then instantly closing). Required so the button works mid-charge: resetting during `CHARGING` needs a second-finger tap while the launch button is held, where click synthesis is unreliable.

## 5. Reset button (R equivalent)

- `#mobile-reset-button` (`↻`, `44×44`, `absolute; top:36px; left:64px` — just right of the hamburger; `z-index:7`): visible on all platforms while gameplay chrome is visible (same rule as the hamburger).
- Click/tap dispatches the identical `R` path as keyboard (`KeyR` keydown handling: reward re-roll when a reward menu is open, `Game Over`/`WIN` continue, `resetBall()` otherwise with last-attempt blocking — per `06-run-rules.md` §§3–4 and `07-rewards-and-economy.md` §4). Synthetic `KeyR` keydown event reused so behavior can never diverge.
- Same `touchend` + `click` firing as the hamburger (§4), so reset works mid-charge via a second-finger tap while the launch button is held (identical to desktop holding `Space` + pressing `R`): the charge is cancelled (`resetCharge`), the ball re-tees, and lifting the launch finger afterwards does not launch. Single-finger flow is unchanged: releasing launch first launches the ball, and reset during that flight follows the normal `FLYING` rules (blocked only on the actual last flight).

## Acceptance

- [ ] Phone UA (or `?mobile=1`) shows fullscreen + 3 touch buttons; desktop shows neither (hamburger + reset show on both).
- [ ] First tap on mobile requests fullscreen + landscape lock attempt (lock chained after fullscreen resolves, not alongside); skipping a cutscene re-asserts fullscreen + lock, never portrait; exiting fullscreen shows `⛶` which re-enters.
- [ ] Portrait viewport in mobile mode shows the rotate guard (blocking touch; charge/reset/placement gated) and hides it on return to landscape — including on iOS where the lock API is missing.
- [ ] Hold left/right rotates aim at keyboard rate; hold-launch charges force bar and releases with identical power/accounting; all blocked in same states as keyboard.
- [ ] Touch drag moves placed bubbles/stacks with snap-on-release; bag→canvas touch drag places; bag tap arms/disarms like click/`1–3`; double-tap inside bubble splits/picks up/deselects exactly like right-click; single-tap places like click.
- [ ] The container fills the viewport in all modes (windowed, F11, mobile `⛶`, installed PWA); the playfield is a centered 16:9 contain box (no stretch, whole level visible) surrounded by OB `#2E2E2E` instead of black bars; mobile chrome sits at the true screen corners and `#hud` spans the full window width; the menu splash is a centered box clamped to 16:9–20:9 (no stretch, capped at 20:9 on ultra-wide); exiting/re-entering fullscreen keeps DPR/input mapping correct.
- [ ] On iOS the fullscreen button shows the Share → Add to Home Screen toast (no fullscreen attempt); installed standalone PWA hides the button and launches fullscreen landscape (see `13-pwa.md`).
- [ ] Hamburger opens/closes exactly like `Escape` in every state (deselect, pause open/resume, dialog dismiss); hamburger/reset fire on `touchend` + `click` (no double-dispatch) so both work mid-charge with a second finger.
- [ ] Second-finger reset tap during `CHARGING` cancels the charge and re-tees with no launch on release (desktop `Space`+`R` parity).
- [ ] Tutorial banters + help show touch wording in mobile mode: `controls-first-mobile` / `tutorial-field-modifiers-mobile` from `src/tutorial-banter-mobile.json` (drag-drop place, double-tap pickup/split, on-screen aim/launch/reset) instead of the desktop ids; help Controls list shows the touch equivalents (desktop list restored off-mobile).
